# 数据包奖励系统设计

> **版本**：v1.0  
> **模式**：安全实践爬塔模式（模式三）  
> **参照系统**：《杀戮尖塔》遗物系统  
> **设计规模**：9层 × 9个 = 81个独特数据包

---

## 一、系统概述

### 1.1 数据包概念

**数据包**是安全实践爬塔模式中的核心永久性奖励道具，玩家在击败每层BOSS后获得。每个数据包代表一种网络安全领域的"知识结晶"或"防护工具"，一旦获取将持续生效直到本局游戏结束。

**核心定位**：
- 类比《杀戮尖塔》中的"遗物"（Relic）系统
- 永久性被动增益，不可丢弃、不可交易
- 效果可叠加，形成独特的Build构建策略
- 每局游戏最多可获得9个数据包（每层1个）

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| **主题绑定** | 每层数据包与该层安全主题强关联，增强叙事感 |
| **效果多样** | 四种效果类型均衡分布，避免单一化 |
| **稀有度分层** | common/uncommon/rare 三级稀有度控制强度 |
| **可组合性** | 不同数据包之间可产生协同效应 |
| **易懂性** | 效果描述一句话说清，降低学习成本 |

## 二、数据包数据结构

### 2.1 TypeScript 接口定义

```typescript
interface DataPacket {
  id: string;              // 唯一标识符，格式：DP_T{tier}_{序号}
  name: string;            // 中文名称
  description: string;     // 效果描述（一句话）
  icon: string;            // 图标描述（供AI绘图参考）
  tier: number;            // 所属层级 (1-9)
  theme: string;           // 主题标签
  effectType: 'buff' | 'passive' | 'trigger' | 'resource'; // 效果类型
  rarity: 'common' | 'uncommon' | 'rare';                  // 稀有度
  designNote?: string;     // 设计创意说明
}

// 效果类型说明：
// - buff：战斗开始/结束时触发的增益效果
// - passive：持续生效的被动修正
// - trigger：特定条件触发的一次性效果
// - resource：资源类修改（金币/抽牌等）
```

### 2.2 稀有度定义

| 稀有度 | 标识 | 出现概率 | 边框颜色 | 强度等级 |
|--------|------|----------|----------|----------|
| common | 普通 | ~50% | 灰白色 #B0B0B0 | ★★☆ |
| uncommon | 稀有 | ~35% | 蓝色 #4A90D9 | ★★★ |
| rare | 史诗 | ~15% | 金色 #D4A017 | ★★★★ |

### 2.3 全局状态追踪结构

```typescript
interface PlayerDataPackets {
  owned: DataPacket[];                    // 已拥有的数据包列表
  activeEffects: ActiveEffect[];          // 当前激活的效果列表
  effectHistory: EffectLog[];             // 效果触发日志（用于调试）
}

interface ActiveEffect {
  packetId: string;
  effectType: DataPacket['effectType'];
  triggerCondition?: string;              // 触发条件
  currentValue?: number;                  // 当前数值状态（如计数器）
  stackCount: number;                     // 堆叠次数
}
```

### 5.3 效果堆叠与冲突处理

#### 5.3.1 堆叠规则

```
堆叠优先级（从高到低）：

1. rare > uncommon > common（同效果类型时，高稀有度优先计算）
2. 后获取 > 先获取（同稀有度时，后获取的覆盖/叠加在前）
3. 百分比效果 = 1 - (1-a)×(1-b)×(1-c)...（递减叠加）
4. 固定数值效果 = a + b + c...（线性叠加）

示例：
  拥有"隔离沙箱"(减30%) + "VPN隧道"(减20%)
  → 实际减伤 = 1 - (1-0.3)×(1-0.2) = 1 - 0.56 = 44%
```

#### 5.3.2 冲突解决表

| 冲突类型 | 处理规则 | 示例 |
|----------|----------|------|
| 同效果不同值 | 取最优值 | 两个"费用-1"效果不叠加，只生效1次 |
| 互斥效果 | 后获取的覆盖先获取的 | "免疫远程攻击" vs "近战减伤"不冲突 |
| 条件冲突 | 都满足时都触发 | "HP<25%" 和 "HP<50%" 可同时触发 |
| 资源限制 | 按获取顺序排队 | 每回合限1次的触发效果，第一个满足条件的先触发 |
| 上限封顶 | 设定硬上限 | 总减伤不超过70%，总增伤不超过100% |

### 5.4 性能考虑

| 问题 | 解决方案 |
|------|----------|
| 效果触发频率过高 | 使用事件总线 + 防抖/节流，避免每帧遍历 |
| 81个数据包的内存占用 | 按需加载，只加载当前层数据包池 + 已拥有 |
| 联动组合爆炸 | 预计算常见组合缓存结果，非常见组合运行时计算 |
| 存档体积膨胀 | 只存储ID数组，效果运行时动态计算 |
| 调试困难 | 内置效果日志面板，可单独开关每个数据包 |

### 5.5 平衡性调优建议

| 调优维度 | 建议 |
|----------|------|
| 前期（1-3层） | 以common为主，效果温和，帮助玩家理解系统 |
| 中期（4-6层） | 引入更多uncommon，效果开始有明确Build导向 |
| 后期（7-9层） | rare增多，效果强力但通常有条件限制 |
| Build多样性 | 确保4种effectType在每个层级都有代表 |
| 反 synergy 控制 | 避免某几个固定组合过于强势导致玩法固化 |
