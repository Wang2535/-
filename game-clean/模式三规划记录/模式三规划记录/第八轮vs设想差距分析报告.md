## 二、逐项差距分析

### 🔴 P0 — 致命级（2项）

#### Gap-P0-1: W/N/I/P 字母仍偏小，未达到"占据象限1/4面积"的设想要求

**设想原文**:
> "W/N/I/P 四个大字母分别填充下圆的四个象限区域"
> "每个字母的尺寸应该足够大，使其成为该区域最醒目的元素"

**海幸参考图特征**:
- 字母几乎占据了各自象限区域的 **30-40% 面积**
- 字母非常粗黑，远距离即可识别
- 字母颜色饱和度高（橙/金黄），与深色背景形成强烈对比

**当前实现**:
```typescript
// QuadrantLabels.tsx 第28行
const baseFontSize = Math.max(r * 2 * (labels[0]?.fontSizeRatio ?? 0.22), 12);
```
- fontSizeRatio = 0.22, 在 viewbox 100x100 中 r≈35 → fontSize ≈ **15.4**
- 这比第七轮的5大了3倍，但相比海幸参考图的"占象限30-40%面积"仍有差距
- 海幸图中字母的视觉占比约为 **半径的35-40%**（即 fontSizeRatio 应为 0.35~0.40）

**差距量化**: 当前 fontSizeRatio=0.22, 目标 ≈0.35 → **差 0.13（约37%偏小）**

**修复方案**: 将 DEFAULT_QUADRANT_LABELS 的 fontSizeRatio 从 0.22 提升到 **0.34~0.38**

---

#### Gap-P0-2: 棋盘格边框的"方格感"不够强

**设想原文**:
> "葫芦形轮廓外围有一圈棋盘格样式的装饰性边框"
> "类似国际象棋棋盘的橙黄白方格交替图案"

**海幸参考图特征**:
- 方格非常清晰、密集
- 方格紧贴葫芦形外轮廓
- 有明显的立体感/厚度感

**当前实现**:
```tsx
// CheckerboardBorder.tsx
const tileSize = borderCfg.tileSize ?? 12; // 方格大小
patternTransform="rotate(15)"              // 旋转15度
opacity={opacity}                          // 0.85透明度
```

**差距分析**:
1. tileSize=12 可能偏大（方格太稀疏），海幸图中方格更密集（可能tileSize=6~8）
2. rotate(15) 的旋转角度可能不是最佳（海幸似乎更接近0°或45°）
3. opacity=0.85 使边框过于透明，海幸中边框更实心
4. 边框缺少"厚度感"——海幸中边框有内外两层

**修复方案**: tileSize→6~8, opacity→0.95, 增加双层边框(内细+外粗)

### 🟠 P1 — 严重级（5项）

#### Gap-P1-1: Boss 格的视觉冲击力不足

**设想**: Boss格应该是整个地图上**最引人注目的元素**
- 面积是普通格子的 **2.5倍** ✅ 已实现
- 有红色脉动光环动画 ✅ 已实现(boss-pulse)
- 有弹性登场动画 ✅ 已实现(boss-emerge)

**仍缺**:
- Boss 格周围缺少 **危险区域标记**（如红色脉冲环扩散到周边格子）
- Boss 格图标（👑皇冠）在 SVG 中可能不够大/不够华丽
- 缺少 Boss 名称标签显示

---

#### Gap-P1-2: 区域背景(W/N/I/P/S/D)的半透明填充不够明显

**设想**: 每个象限区域应有**明显的半透明色彩覆盖**

**当前实现**:
- zoneBackgrounds 数据已定义 fillColor（如 W区 rgba(255,107,107,0.12)）
- 但 opacity=0.12 太淡了！肉眼几乎看不到区域区分

**海幸特征**: 区域色彩覆盖更明显（opacity 约 0.20~0.30）

**修复**: 各区域 fillColor opacity 从 0.12 提升到 **0.18~0.25**

---

#### Gap-P1-3: 背景装饰元素的丰富度不足

**海幸参考图特征**:
- 上圆区域有**大型星球+多层光圈+小行星带**
- 背景有**云朵漂浮层**
- 可能有**山脉剪影**或**数据流线条**
- 整体氛围感很强（像一幅科幻插画）

**当前实现**(L1):
- 1个 planet + 4个 crystal + 2个 data-stream = **7个装饰元素** ✅ 数量不错
- 但每个装饰元素的**视觉复杂度偏低**（planet只是一个简单圆+渐变）

**差距**: 装饰元素需要更多细节（如 planet 加上环形轨道/crystal 加上光芒射线）

---

#### Gap-P1-4: 玩家棋子的 DOM 覆盖层问题

**当前实现**:
AnimationLayer.tsx 第140行使用了 `<div>` 作为玩家棋子容器：
```tsx
return (
  <div style={{
    position: 'absolute',
    left: `${x}%`, top: `${y}%`,
    transform: 'translate(-50%, -50%)',
    pointerEvents: 'none',
    zIndex: 20,
  }}>
    {/* 玩家棋子内容 */}
  </div>
);
```

**问题**: 这个 div 覆盖在 SVG 之上，可能导致：
1. 坐标系微小不对齐（SVG用viewBox坐标，div用百分比）
2. 缩放时不同步

**理想方案**: 完全在 SVG 内部渲染玩家棋子（使用 `<g transform="translate(...)">`）

---

#### Gap-P1-5: 曲线连接线的视觉表现力弱

**设想**: 连接线应该有**方向箭头**和**动态流动效果**

**当前实现**:
- 使用贝塞尔曲线(Q命令)连接格子 ✅
- 不同路径类型有不同颜色 ✅
- 但缺少：箭头指示方向 / 流动粒子效果 / hover高亮

### 🟡 P2 — 中等级（10项）

#### Gap-P2-1: CSS 动画未被正确注入DOM

**问题**: `gourdAnimations.ts` 导出的是 JS 对象而非 .css 文件。虽然 `styles.css` 中有完整的 `.gm-*` 规则，但需要确认运行时这些类名确实被应用到了对应元素上。

#### Gap-P2-2: 各层级(L1-L9)的视觉差异化不明显

L1-L9 应该有显著不同的主题色和装饰风格，但目前只有 background.primary 和 decorations 有差异。

#### Gap-P2-3: 缺少关卡信息面板

设想中每层应有：关卡名称、难度星级、当前进度等UI信息展示。

#### Gap-P2-4: 格子hover/点击反馈不够明显

CellNode 的 cursor 和 onClick 存在，但缺少 hover 时的视觉变化（如放大/发光）。

#### Gap-P2-5: 路径线缺少动画效果

主线应有微弱的"能量流动"动画效果。

#### Gap-P2-6: 十字分割线太细

当前 strokeWidth="0.8"，在海幸参考图中分割线更粗更清晰。

#### Gap-P2-7: 缺少"已完成"格子的金色闪光轨迹

设想中走过并通关的格子应有永久性的金色标记。

#### Gap-P2-8: 锁定格子的灰化效果可以更强

当前 locked opacity=0.35，可以考虑加上模糊滤镜。

#### Gap-P2-9: 层级切换过渡动画缺失

切换 L1→L2 时应有平滑的过渡效果。

#### Gap-P2-10: 移动骰子UI未集成

设想中有骰子系统来决定移动步数，目前尚未与渲染器对接。

## 四、第九轮开发建议

基于以上差距分析，建议第九轮聚焦以下**最高优先级**任务：

### 第九轮 A组建议: 无重大变更
- 当前资源库已基本完善
- 可选: 增加 2-3 种特殊格子图标（如 treasure/key/potion）

### 第九轮 B组建议: 关键参数精调
1. **quadrantLabels.fontSizeRatio**: 0.22 → **0.36** （最大单项提升）
2. **zoneBackgrounds fillColor opacity**: 0.12 → **0.22** （区域可见性）
3. **border.tileSize**: 12 → **7** （方格密度）
4. **border.opacity**: 0.85 → **0.95** （边框实心度）
5. **crossDivider strokeWidth**: 0.8 → **1.5** （分割线清晰度）

### 第九轮 C组建议: 无重大变更
- fallback 逻辑已完善
- 可增加 topology 输出后的最终校验日志

### 第九轮 D组建议: 完善 MovementController
- 确保 MovementController 封装完整可用
- 增加 keyboard/mouse 事件监听（用于手动测试移动流程）

### 第九轮 E组建议: 4项关键升级
1. **P0**: AnimationLayer 从 DOM div 迁移到纯 SVG `<g>`
2. **P0**: Boss 格增加**周边危险区域脉冲环**（额外 SVG circle + animate）
3. **P1**: 连接线路增加**方向箭头**（path marker-end）
4. **P1**: 格子增加 **hover 放大效果**（CSS transform scale）

### 第九轮 F组建议: 执行完整的手动验证清单
- 40项逐项检查
- 截图存档作为基线
